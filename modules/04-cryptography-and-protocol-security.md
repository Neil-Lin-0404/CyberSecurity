# 模組 04 — 密碼學與協定安全

[模組 03](03-software-and-web-security.md) · [數學](../foundations/mathematics.md) · [模組 05](05-digital-forensics-and-incident-response.md)

## A. 概述

這個領域研究如何用數學定義與構造保護機密性、完整性與鑑別，以及真實協定在組合這些構造時哪裡會錯。它同時包含兩件容易被混成一件的事：密碼原語（加密、雜湊、簽章）與密碼協定（TLS、金鑰交換、認證握手）。

學會演算法步驟，甚至會呼叫函式庫，都不等於會設計安全協定。協定要處理訊息順序、金鑰的生命週期、身分綁定、重送、失敗時洩漏的資訊，以及參與者對時間與隨機性的假設。

它被用在傳輸安全、軟體簽章、憑證、密碼儲存、端到端加密與許多隱私構造。研究工作也包含證明一個定義被滿足，或給出定義沒蓋到的攻擊。

和 [網路安全](01-network-security.md) 的分工：本模組問「這個密碼性質在所述對手模型下是否成立」；網路模組問「部署與路徑讓這個性質沒有被用上」。和 [形式方法](12-formal-methods-and-program-analysis.md) 的分工：協定的符號模型檢查可以放在形式方法，密碼學歸約證明仍以本模組的定義為準。

## B. 研究問題

1. 一個加密方案若沒有完整性，對手改動密文時，解密端會產生什麼類別的失敗？
2. 雜湊適合拿來做什麼，為什麼它本身不是鑑別？
3. 憑證鏈驗證若跳過主機名稱檢查，TLS 還剩下哪些性質？
4. 金鑰重用與隨機數重用會讓哪個構造的安全定義直接不適用？
5. 一個玩具握手在哪一步把身份綁到金鑰？若拿掉該步驟，對手可以扮演誰？
6. 實作若在錯誤的分支提早返回，時間差異可能洩漏什麼？這一題只到能陳述問題，不做到量測利用。

## C. 研究者實際在做的事

- 讀安全定義：對手能做什麼、什麼算贏。
- 用函式庫正確完成加密與驗證，並寫測試。
- 比較兩種 API 哪一個會讓呼叫者忘記檢查驗證結果。
- 把協定畫成訊息序列，標出每個訊息依賴的金鑰。
- 閱讀證明的假設，而不是每一步都重證。
- 對玩具協定找概念上的失敗：重送、反射、缺少綁定。
- 在更後面才做：機器檢查的證明、常數時間實作、新構造。

吸引人的版本是「設計打不破的加密」。日常更常是讀定義、找組合錯誤、檢查實作是否用錯函式庫。

## E. 知識路線

### Stage 0 — 入門

概念：古典密碼只作為歷史對照，說明沒有定義的「看起來很亂」不是安全。對稱與非對稱的分工。隨機性是輸入，不是裝飾。

成果：用自己的話說出凱撒密碼缺少的對手模型。

可延後：古典密碼的各種變體。

### Stage 1 — 核心概念

概念：對稱加密、雜湊、MAC、非對稱加密與簽章的用途差別、金鑰交換在建立共享秘密、PKI 用憑證把公鑰綁到名稱。

成果：一張表，每種原語保證什麼、不保證什麼。

可延後：演算法內部回合。

### Stage 2 — 技術理解

概念：安全定義的形狀（雖不必寫歸約）、完整性與機密性必須分開、數位簽章與 MAC 的金鑰差異、憑證驗證要檢查鏈、用途與名稱。

成果：畫 TLS 1.3 的概念圖：誰被認證、從何時起應用資料受保護。規格 RFC 8446 只讀簡介。

可延後：群、有限體的運算細節。

### Stage 3 — 實作與分析

概念：使用受維護的函式庫、檢查驗證結果、金鑰與隨機數的生命週期、常見實作錯誤（硬編金鑰、自製加密、只加密不驗證、錯誤處理洩漏明文路徑）。

成果：一個玩具協定的訊息圖與假設清單，使用函式庫完成 MAC 或簽章驗證。不要發明加密演算法。

練習環境：本機程式。[CryptoHack](https://cryptohack.org/) 只用站內或它指定的教學題，用來理解原語，不對別的系統使用。

可延後：常數時間程式設計的技術細節、側信道實驗。

### Stage 4 — 研究題

證明與計算假設、協定組合、形式化驗證過的實作、密碼誤用的系統性研究、後量子遷移的工程問題（先 L0：知道現有某些公鑰假設與量子計算的研究關係，不把新方案當入門）。

成果：選一個定義，寫出對手能力與你讀不懂因而暫緩的證明步驟。

可延後：完整形式化證明系統、新密碼構造的設計。

## G. 論文入口

教材先於單篇論文：

- Dan Boneh、Victor Shoup。*A Graduate Course in Applied Cryptography*。[toc.cryptobook.us](https://toc.cryptobook.us/)。從導論與對稱加密的安全定義讀起。這是教科書，不是會議論文。
- Boneh 的課程頁：[Online Cryptography Course](https://crypto.stanford.edu/~dabo/courses/OnlineCrypto/)。

會議：IACR 的 Crypto、Eurocrypt、Asiacrypt 偏密碼理論與構造；協定與實作也出現在 IEEE S&P、USENIX Security、CCS、NDSS。IACR 的公開資料庫是 [ePrint](https://eprint.iacr.org/)。預印本不一定等於審查後版本。

不要從「最新的構造」開始。先把一本教材裡的一個定義讀到能複述對手模型。經典論文在你有定義之後，由教材的參考文獻選，避免在沒有核對的情況下抄書目。

RFC 8446 是協定規格入口，不是安全證明。

## I. 自我評估

1. 你是否願意在寫程式之前先寫「對手贏了代表什麼」？
2. 你是否覺得讀定義比收集密碼套件名稱有趣？
3. 你是否接受許多構造你只需會用並知道假設，不必自己發明？
4. 你是否願意把一個能跑的玩具協定仍標成不安全，因為假設不成立？

若你喜歡立刻寫大量程式而抗拒定義，先做網路或系統模組，把本模組留到需要 TLS 或簽章時再以 Stage 1 補上。
