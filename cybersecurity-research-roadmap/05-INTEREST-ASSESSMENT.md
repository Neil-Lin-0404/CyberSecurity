# 興趣評估

[研究法](04-RESEARCH-METHODOLOGY.md) · [地圖](README.md) · [學術與職涯](06-RESEARCH-CAREER-AND-ACADEMIA.md)

這不是心理測驗，也沒有常模或診斷意義。它用來區分「主題聽起來有趣」和「你願意做這個領域的日常工作」。分數只幫你排探索順序。

評分：1 很不願意，2 不太願意，3 可以試試，4 願意花一個下午，5 願意連續做幾週。對每個句子誠實打分，並在旁邊寫一句原因。

## 先分開的偏好

這些分數不對應單一專長，用來解讀後面的結果。

| 編號 | 句子 | 分數 |
|---|---|---|
| P1 | 我願意為了一個定義反覆改寫，直到假設精確 | |
| P2 | 我願意為了觀察系統行為寫程式、改條件、重跑 | |
| P3 | 我喜歡從規格或模型推出必須成立的性質 | |
| P4 | 我喜歡從資料裡找與預期不符的現象 | |
| P5 | 我想做的是讓防禦更清楚、更好量測 | |
| P6 | 我想找出現有系統沒說出口的限制 | |
| P7 | 我比較想處理封包、核心、硬體這類系統層問題 | |
| P8 | 我比較想處理應用、身分、介面與政策 | |
| P9 | 遇到看不懂的數學，我願意先學到剛好夠用的深度 | |
| P10 | 遇到漫長的除錯，我願意留在同一個問題上 | |

P1、P3、P9 偏高：理論與形式工作可能適合抽樣。P2、P4、P10 偏高：量測、系統與實作分析可能適合。P5 與 P6 可以同時高，許多研究兩者都要。P7 與 P8 幫你避免只因名稱選邊。

## 十五個專長的情境

每個專長兩題。題號對應模組編號。

### 01 網路安全

- N1 你願意花數小時弄清自己的程式為什麼封包遺失或重送嗎？
- N2 你願意讀一份協定規格，並寫下它假設對手不能做什麼嗎？

### 02 系統安全

- S1 你願意追蹤一次系統呼叫如何穿過使用者態與核心態的邊界嗎？
- S2 你願意比較兩種隔離方式各自擋住什麼、擋不住什麼嗎？

### 03 軟體與 Web

- W1 你願意畫一個 Web 應用的信任邊界，並指出哪個檢查被漏掉嗎？
- W2 你願意在授權的教育應用裡觀察輸入如何變成不安全的行為，然後寫下防禦嗎？

### 04 密碼與協定

- C1 你願意弄清一個定義在保證什麼，而不是只會呼叫函式庫嗎？
- C2 你願意設計一個玩具協定，再故意列出它會失敗的假設嗎？

### 05 鑑識與事件回應

- F1 你願意從給定的日誌重建事件順序，並標出時間不可靠的地方嗎？
- F2 你願意為了證據完整性記錄雜湊、工具版本與保管步驟嗎？

### 06 逆向與惡意程式分析

- R1 你願意看自己編譯的程式的反組譯，對照原始碼理解控制流嗎？
- R2 你願意在隔離環境裡觀察程式行為，並拒絕執行來路不明的檔案嗎？

### 07 雲端與基礎設施

- K1 你願意讀一個叢集的權限與網路隔離設定，找出過度授權嗎？
- K2 你願意把「誰能呼叫控制平面」寫成可檢查的清單嗎？

### 08 硬體與嵌入式

- H1 你願意從資料手冊理解一個介面在傳遞什麼，而不是只跑現成韌體嗎？
- H2 你願意用你擁有的板子或模擬器檢查開機信任鏈的每一步假設嗎？

### 09 身分與存取

- I1 你願意比較兩種存取控制模型在同一個小系統上的允許與拒絕嗎？
- I2 你願意讀 OAuth 或類似流程，指出令牌被拿到之後還能做什麼嗎？

### 10 AI 安全

- A1 你願意用合成資料設計實驗，看模型在什麼條件下行為改變嗎？
- A2 你願意把提示注入當成系統設計問題，檢查工具權限與資料邊界嗎？

### 11 隱私

- V1 你願意檢查一份合成資料是否仍能讓人推論出個人，並說明原因嗎？
- V2 你願意閱讀差分隱私的定義，弄清它保證的是什麼、不是什麼嗎？

### 12 形式方法

- M1 你願意為一個小狀態機寫不變式，並用工具找反例嗎？
- M2 你願意把「這個安全性質成立」寫成可以檢查的陳述嗎？

### 13 情資、歸因與量測

- T1 你願意把一條技術證據標成基礎設施線索，並拒絕把它写成某個人的身份嗎？
- T2 你願意討論證據品質、替代解釋與錯誤歸因的後果嗎？

### 14 安全工程與供應鏈

- E1 你願意追蹤一個依賴如何進入建置，並記錄你能驗證什麼嗎？
- E2 你願意為了可重現建置而整理版本、來源與檢查步驟嗎？

### 15 人因與安全經濟學

- U1 你願意設計一個小實驗，看介面如何改變人的安全決策嗎？
- U2 你願意分析一個安全政策獎勵了什麼行為、忽略了什麼成本嗎？

## 計分與解讀

對每個專長，把兩題相加（2–10）。

- 8–10：優先抽樣。進入該模組 Stage 0–1，並做一個觀察練習。
- 5–7：保留。先完成更高分領域的 Stage 1，再決定要不要看。
- 2–4：目前不投入。若只是主題名稱吸引你，而分數低，把它記成「聽起來有趣，日常工作可能不合」。

另外檢查：

- 若某領域只有一題高、一題低，證據不足。再做該模組的一個練習後重評。
- 主修選總分最高且 P10 不低的領域。互補選一個分數次高、且與主修共享證據類型的領域。例如網路與歸因都處理不完整觀察；密碼與形式方法都處理定義。
- 不要用單一高分否定基礎缺口。分數高仍須滿足該模組的 REQUIRED 先修。

## 建議的下一步對照

| 若最高分是 | 先做的入門專題 |
|---|---|
| 網路或歸因 | [初學專題](projects/beginner-projects.md) 的自有流量觀察 |
| 系統或逆向 | 對照自己程式的系統呼叫或反組譯 |
| 密碼或形式方法 | 玩具協定的假設清單，或小狀態機 |
| Web、身分或供應鏈 | 畫出一個你自己的小應用的信任邊界 |
| 鑑識 | 用公開教育資料集做時間線，先讀使用條款 |
| 隱私或 AI | 只用合成資料做洩漏或行為比較 |
| 人因 | 比較兩個登入介面的決策成本，不對真人施壓 |

把結果抄進 [進度](PROGRESS-TRACKER.md) 的「專長假設」一節。六到八週後，只用這段時間的練習重評一次。
