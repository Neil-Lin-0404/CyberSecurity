學習類型以概念為主。演算法分析碰到的數學保持在總和與數量級，不把微積分設成 REQUIRED。

## 現在要穩固的部分

你已接觸演算法。這裡要求的是能把概念用在系統與實驗上，而不是再上一門完整課程。

| 主題 | 深度 | 重要性 | 原因 |
|---|---|---|---|
| 資料結構與演算法 | L1 | REQUIRED | 讀研究程式與估計實驗成本 |
| 時間與空間複雜度 | L1 | REQUIRED | 判斷分析腳本能否處理你的資料 |
| 資料表示、二進位與十六進位 | L2 | REQUIRED | 封包、檔案與記憶體都是位元組 |
| 記憶體模型的程式觀點 | L1 | REQUIRED | 和 [計算機結構](computer-architecture.md)、[作業系統](operating-systems.md) 銜接 |
| 行程、執行緒、並行的語意 | L1 | REQUIRED | 隔離與資料競爭 |
| 分散式系統的故障 | L0 | RECOMMENDED | 網路與雲端研究預設節點會失敗、時鐘會漂 |
| 資料庫 | L0 | OPTIONAL | 只有日誌、鑑識或應用研究需要查詢模型時升到 L1 |
| 軟體架構 | L1 | RECOMMENDED | 能畫出元件與信任邊界即可，見 [軟體工程](software-engineering.md) |

## 資料表示

整數的寬度、有號表示、位元組序（endianness）、字串與長度欄位是網路與檔案格式的共同基礎。深度 L2：給你一段十六進位，你能指出哪幾個位元組可能是長度或位址，並說出你還不能確定什麼。

字元編碼在 Web 與鑑識裡重要，先到 L0：知道位元組序列不等於你看到的字元。

## 複雜度怎麼用在研究

你不需要為每個腳本寫證明。你需要能說：雙重迴圈掃一份擷取會不會比線性掃描多一個數量級。若實驗跑不完，先改演算法或取樣，而不是先換研究問題。取樣本身會帶來偏差，必須寫進限制。

## 分散式系統只需要這些

L0 就夠開始：沒有全域時鐘、訊息會延遲、遺失與重送、部分失敗是常態。一致性模型、共識演算法是 OPTIONAL，除非你的問題是分散式正確性或區塊鏈類系統。不要為了了解 HTTPS 先學 Paxos。

## 資料庫

知道資料表、索引與「查詢結果依賴你寫的條件」即可。交易隔離層級在你研究並行資料存取時才是 ON-DEMAND。

## 自測

1. 把一個 32 位元整數用手寫成 big-endian 與 little-endian 的四個位元組。
2. 說明行程與執行緒在共享記憶體上的差別。
3. 給一個雙迴圈分析，估計當輸入變成十倍時工作量大概變多少。
4. 舉一個「訊息延遲」會讓簡單狀態機判斷錯誤的例子。深度停在故事層，不必形式化。
